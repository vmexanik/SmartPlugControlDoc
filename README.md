# Сайт-інструкція Smart Plug Control

Публічний репозиторій сайту-інструкції та прошивок. Код прошивки лежить окремо (`SmartPlugControl`).

Статичний сайт (чистий HTML/CSS/JS, без збірки й залежностей). Публікується через GitHub Pages з кореня гілки `main`.

## Прошивки (GitHub Releases)

Кожна версія — реліз із тегом `vX.Y.Z` у цьому репо з двома файлами:

| Файл | Що це |
|---|---|
| `smart_plug_control-X.Y.Z.bin` | звичайна збірка |
| `smart_plug_control-X.Y.Z-eng.bin` | інженерна збірка (діагностика) |

`firmware.html` читає список релізів через GitHub API і показує селект версій. Pre-release = бета (прихована за прапорцем), draft не показується. Посилання на конкретну версію: `firmware.html#v2.1.6`.

Публікація з репо коду (після `idf.py build` обох варіантів; файли з версією в назві лежать у `release/`):

```powershell
.\tools\publish_release.ps1 -NotesFile notes.md        # -Beta для бета, -SkipEng якщо немає інженерної
```

Потрібен GitHub CLI (`winget install GitHub.cli`, далі `gh auth login`). Примітки пишуться в Markdown (заголовки, списки, `код`, **жирний**, посилання).

## Версії документації

Документація ведеться **за мажорними лініями прошивки** (2.x, 3.x…), а не за кожним релізом: мінорні й патч-версії
описуються в поточній документації (у примітках до релізу або позначкою «з версії 2.2» на сторінці).

- **Корінь сайту** завжди описує поточну лінію, тож адреси поточної документації не змінюються.
- **Старі лінії** заморожені в теках `2.x/`, `3.x/`… і більше не редагуються (хіба що виправлення помилок).
- `versions.json` містить список ліній: `id`, `path` (тека відносно кореня, `""` для поточної), `match` (regex тегів релізів),
  `latest`.
- Перемикач «Документація для прошивки» в меню з'являється, коли ліній більше однієї, і відкриває ту саму сторінку
  в іншій лінії (або головну, якщо такої сторінки там немає). На старих лініях угорі є банер із посиланням на поточну.
- На `firmware.html` релізи згруповані за лініями. Якщо вибрати версію з іншої лінії, відкривається сайт тієї лінії.

Перед виходом нової мажорної версії:

```powershell
python archive-docs.py 3.x --dry-run    # що буде скопійовано
```
```powershell
python archive-docs.py 3.x              # корінь -> 2.x/, корінь стає 3.x
```

Після цього оновлюйте сторінки в корені під 3.x. Інтерактивне демо в замороженій теці лишається від останньої 2.x.

## Публікація (один раз)

1. Репозиторій має бути **публічним** (для безкоштовного плану).
2. GitHub → **Settings → Pages → Build and deployment**:
   - Source: **Deploy from a branch**
   - Branch: **main**, folder: **/ (root)** → Save.
3. Через ~1 хв сайт буде доступний на `https://vmexanik.github.io/SmartPlugControlDoc/`.

Далі кожен `git push` у `main` сам перепублікує сайт. Якщо репо перейменуєте, змініть `REPO_SLUG` в `assets/site.js` і `-Repo` за замовчуванням у `tools/publish_release.ps1` репо коду.

## Локальний перегляд

```bash
python -m http.server 8000
# відкрити http://localhost:8000
```

Не відкривайте файли подвійним кліком (`file://`): демо використовує `fetch`, а той у браузерах на `file://` обмежений.

## Структура

```
./
  index.html … faq.html     сторінки (кожна самодостатня, навігація додається з assets/site.js)
  assets/site.css           стилі (світла/темна тема)
  assets/site.js            меню, «Далі/Назад», кнопки «Копіювати», перемикач теми, REPO_SLUG
  assets/firmware.js        селект версій на firmware.html (GitHub Releases API)
  demo/                     інтерактивне демо веб-інтерфейсу (див. нижче)
  sync-demo.py              оновлення демо з main/web/
  versions.json             лінії документації (перемикач версій)
  archive-docs.py           заморожування лінії перед мажорним оновленням
  .nojekyll                 вимикає обробку Jekyll
```

### Додати сторінку

1. Скопіюйте будь-яку сторінку (наприклад `faq.html`) і змініть вміст у `<main>`.
2. Додайте рядок у масив `PAGES` у `assets/site.js`: меню й «Далі/Назад» оновляться самі.

## Демо веб-інтерфейсу

`demo/` це **справжній** інтерфейс прошивки (`main/web/` репо коду) із підміненим API: `demo/mock.js` перехоплює `fetch('/api/…')` і відповідає вигаданими даними. У правому нижньому куті є симулятор входів: повзунок напруги й прапорці DC1/DC2.

Після кожної зміни `main/web/*` запускайте:

```bash
python sync-demo.py            # код шукається в ../SmartPlugControl, або передайте шлях
```

Скрипт скопіює `app.js`, `style.css`, `favicon.svg`, переробить `index.html` (відносні шляхи + підключення `mock.js`) і зупиниться з помилкою, якщо структура `index.html` змінилась так, що перетворення не спрацювало.

Якщо у прошивці з'явився новий ендпоінт `/api/…`, додайте його у функцію `route()` в `demo/mock.js`. Поки цього не зроблено, демо показує повідомлення «У демо цей запит не підтримується».

## Що підтримувати разом із кодом

Сторінки написані за кодом прошивки версії 2.1.x. Якщо змінюється поведінка, оновіть відповідну сторінку:

| Зміна в прошивці | Сторінка |
|---|---|
| Піни, `Kconfig.projbuild` | `hardware.html`, `maintenance.html` (таблиця параметрів) |
| Логіка входів, інверсія, затримка | `hardware.html`, `interface.html` |
| Межі/калібрування AC | `ac.html` |
| Нові драйвери, нові сімейства в пошуку | `devices.html` |
| Поля форм/вкладки UI | `interface.html` (+ `sync-demo.py` для демо) |
| Розмітка пам'яті, OTA | `maintenance.html` |
| Нова версія | реліз через `publish_release.ps1` (сайт підхопить сам) |

Розетки та протоколи

Тут перелік того, що підтримується, і як налаштувати кожен тип.

Що підтримується

Тип Автопошук Стан при додаванні Додаткові параметри відображення
Shelly Gen1 (Plug, Plug S, Shelly 1…) так так потужність (Plug / Plug S)
Shelly Gen2 / Gen3 (Plus, Pro…) так так потужність, напруга, струм
Tasmota так так де є енергомонітор (Sonoff S31, POWR3…)
ESPHome (з web_server:) так так потужність, напруга, струм (якщо є такі сенсори)
Довільний HTTP ні ні ні
MQTT ні ні ні

Shelly і Tasmota

Найкраще рішення. У формі розетки оберіть Shelly (Gen1), Shelly (Gen2+/Gen3) або Tasmota і введіть IP-адресу. Протокол роботи вже реалізований. Або скористайтеся автопошуком, і форма заповниться сама.

  • Якщо на пристрої увімкнено пароль, його видно в пошуку як «(потрібен пароль)». Логін і пароль вводяться у формі розетки.
  • Для Shelly і Tasmota хаб показує споживання, якщо розетка його вимірює.
Tasmota 15.5 і новіші: увімкніть HTTP API З версії 15.5 Tasmota постачається з вимкненим HTTP API: веб-сторінка розетки відкривається, а команди хаба (/cm?cmnd=…) вона відкидає. Хаб розпізнає це: у пошуку й на картці така розетка позначена «(вимкнено HTTP API)». Увімкніть на розетці Configuration → Other → HTTP API, збережіть і натисніть «Перевірити» на картці.

Які команди надсилає хаб

Корисно знати, якщо розетку треба перевірити вручну чи налаштувати файрвол.

Тип Увімкнути
Shelly Gen1 GET /relay/0?turn=on
Shelly Gen2+ GET /rpc/Switch.Set?id=0&on=true
Tasmota GET /cm?cmnd=Power1%20On
ESPHome POST /switch/<id>/turn_on

Вимикання відрізняється останнім словом (off / false / Off / turn_off).

Лише перший канал Автоматично підставляється керування першим каналом (Shelly id=0, Tasmota Power1). Багатоканальні пристрої (подовжувачі, багатоканальні реле) в пошуку позначені як «реле», а адреси для каналів 2+ потрібно вказати вручну в режимі «HTTP».

ESPHome

Хаб керує ESPHome-пристроями через їхній вбудований веб-сервер (REST), той самий, що відкривається в браузері за IP пристрою. До native API (порт 6053, як у Home Assistant) хаб лише підключається і тримає з'єднання, щоб розетка не перезавантажувалась (див. нижче).

  1. Увімкніть веб-сервер у YAML пристрою Потрібен компонент web_server:. Без нього пристрій не керується і не розпізнається пошуком. Якщо задано auth:, введіть ці логін і пароль у формі розетки (підходить і Basic, і Digest — хаб визначить сам).
  2. Оберіть драйвер «ESPHome» і введіть IP Або клікніть пристрій у автопошуку.
  3. Натисніть «Знайти сутності» Хаб за 1–3 с читає список сутностей пристрою. Якщо перемикачів кілька (реле, світлодіод…), оберіть потрібний у списку. Сенсори потужності, напруги й струму підставляються самі, якщо вони є.

Хаб опитує стан перемикача, тож перемикання кнопкою на корпусі чи з Home Assistant видно в інтерфейсі. Перевірено на Athom Smart Plug V3.

Щоб розетка не перезавантажувалась кожні 15 хв

У ESPHome є захист api: reboot_timeout (за замовчуванням 15 хв): якщо за цей час до native API не підключився жоден клієнт (зазвичай Home Assistant), пристрій перезавантажується. Без Home Assistant розетка ребутилася б кожні 15 хв і, залежно від налаштування, при цьому вимикала б реле.

  • З прошивки 2.1.8 хаб сам тримає з'єднання з native API кожної ESPHome-розетки, тож ребутів немає. Нічого налаштовувати не треба.
  • Якщо на API розетки ввімкнено шифрування (api: encryption: key) або пароль, хаб підключитися не може. На картці тоді з'являється «(перезавантажується кожні 15 хв)». Вихід: перепрошити розетку з api: reboot_timeout: 0s або без шифрування/пароля API.
  • Порада для будь-якої ESPHome-розетки: задайте Power On State = Restore Power Off State (у YAML — restore_mode: RESTORE_DEFAULT_OFF). Тоді після перезавантаження чи зникнення живлення реле повернеться в той стан, у якому було, а не вимкнеться. Хаб і так перевіряє стан розетки, коли вона повертається на зв'язок. 
api:
  reboot_timeout: 0s   # не перезавантажуватись без клієнта API

switch:
  - platform: gpio
    # ...
    restore_mode: RESTORE_DEFAULT_OFF
ESPHome 2026.7 і новіші У нових версіях ESPHome адреси сутностей будуються за назвою (/switch/Relay 1), а старі (/switch/relay_1) перестають працювати. Хаб із прошивки 2.1.8 підтримує обидва формати. Якщо розетку додали раніше, а потім оновили ESPHome, картка покаже «(не той драйвер?)». Відкрийте налаштування розетки, натисніть «Знайти сутності» і збережіть.

Довільний HTTP

Підійде будь-який пристрій, який вмикається звичайним HTTP-запитом:

  • URL для увімкнення і URL для вимкнення: повні адреси, наприклад http://192.168.1.50/relay/0?turn=on.
  • Прапорець POST замість GET: для пристроїв, яким потрібен POST.
  • Логін і пароль: якщо пристрій вимагає Basic-авторизацію.

Підтримується лише http://, без шифрування.

MQTT

  1. Задайте брокера Вкладка «Системні налаштування», розділ MQTT: URI (mqtt://192.168.1.10:1883), за потреби користувач і пароль, потім «Зберегти налаштування».
  2. Додайте розетку з драйвером MQTT Вкажіть топік команди (наприклад shellies/shelly1/relay/0/command) та тексти ON/OFF (on / off).
  3. Оберіть QoS і Retain Для більшості випадків QoS 0 без Retain. Retain корисний, якщо пристрій має підхопити останню команду після перепідключення до брокера.

Хаб лише публікує команди. Стан розетки він із MQTT не читає, тому в таких розеток немає опитування стану та показів потужності.

Коли розетка недоступна

Для розеток з розпізнаним типом (Shelly, Tasmota, ESPHome) хаб раз на 10 с перевіряє, чи вони «на зв'язку». Позначка з'являється лише після двох невдалих перевірок поспіль, і на картці написано причину:

На картці Що означає Що робити
(не на зв'язку) Розетка не відповідає: знеструмлена, поза Wi-Fi, змінила IP. Перевірте живлення й мережу. Хаб перевіряє її все рідше (до разу на 5 хв).
(вимкнено HTTP API) Tasmota 15.5+ з вимкненим HTTP API. Увімкніть HTTP API.
(не той драйвер?) Пристрій відповідає, але не так, як вибраний тип (404 або чужа відповідь). Перевірте тип і адресу у формі розетки. Для ESPHome — ще раз «Знайти сутності».
(потрібен пароль) Розетка вимагає логін і пароль, або вони невірні. Вкажіть їх у формі розетки.
  • Поки розетка недоступна, кнопка сіра: команди на неї не надсилаються.
  • Помилки налаштування самі не минуть, тож такі розетки хаб перевіряє лише раз на 15 хв. Кнопка «Перевірити» на картці перевіряє одразу — натисніть її після виправлення.
  • У журнал подій пишеться один запис, коли проблема з'явилась, і один, коли розетка повернулась. Після повернення хаб оновлює її справжній стан (наприклад, якщо хтось натиснув кнопку на корпусі).

Для довільного HTTP та MQTT такого опитування немає, тому вони вважаються доступними завжди.
